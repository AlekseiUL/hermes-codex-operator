# RFC-0002: Existing-task observation and bounded mutation

**Status:** Implemented in the `v0.1.0` candidate; release qualification pending
**Audience:** maintainers, adapter authors, and reviewers
**WorkContract version:** unchanged at `1`
**Journal version:** `5`

## 1. Purpose

Extend the reliable lifecycle without turning Operator into a general
orchestrator. The extension adds bounded discovery, read-only watching, one
idle-thread continuation path, and one exact-version active-thread queue path.
Each operation still maps to at most one automatically dispatched Codex turn.

## 2. Durable dispatch kind

Every operation atomically reserves one immutable `dispatch_kind`:

- `ordinary` — create or resume through the baseline lifecycle;
- `continue` — add one turn to an exact idle existing thread;
- `queue` — enqueue once behind an exact active owner.

Generic `submit`, `recover`, or `collect` may observe an existing nonordinary
operation but cannot reinterpret its kind or dispatch through another path.
SQLite migrations from journal versions 1–4 preserve existing operations and
backfill the kind from continuation or queue baselines where present.

The queue state machine adds `QUEUE_DISPATCH_IN_FLIGHT` between `READY` and
`RUNNING`. It is persisted before `thread/queue/add` can have a side effect.

## 3. Read-only observation

`catalog` and `catalog read` use bounded `thread/list` and authoritative
`thread/read`. `adopt` and `watch` pin an exact `threadId` plus `turnId` and emit
a digest-only completion event. These commands never start, resume, or mutate a
Codex turn. The core has no background daemon and does not deliver Telegram
messages itself.

## 4. Idle continuation

`continue` requires an exact thread ID, canonical workspace match, authoritative
`idle` state, and a persisted baseline of all existing turn IDs. It performs at
most one `thread/resume` and one `turn/start`. The returned turn is accepted only
when it is the sole new turn and exact readback agrees.

After exact correlation is persisted as `RUNNING`, timeout recovery follows
that exact turn and cannot dispatch again. Before correlation, a crash or
ambiguous response is observation-only; explicit `abandon` may close the local
operation so a later operation can proceed.

## 5. Active-thread shared queue

`queue` is an experimental, exact-version opt-in for Codex 0.149.0. It requires:

1. the user to start the managed App Server explicitly;
2. the exact `socketPath` and `appServerVersion` returned by the read-only
   `codex app-server daemon version` command, followed by a direct
   `websockets` connection to `/rpc`, selected by `--shared-app-server`;
3. one exact loaded thread, workspace, and active owner turn;
4. an immutable baseline plus one client-message ID and normalized-input
   digest;
5. bounded authoritative `thread/read` polling for owner and target completion,
   because `turn/completed` may be local to another WebSocket connection;
6. no second enqueue after timeout, malformed response, crash, or restart.

The resulting turn must contain the exact client-message ID and input digest.
Owner and target terminal notifications must agree with authoritative
`thread/read`. The exact queued submission must be absent. Immediately before
`VERIFIED`, Operator rereads the turn, thread/workspace identity, result, and
queue absence; any contradiction becomes `UNKNOWN`.

The managed-daemon CLI path has synthetic coverage but still requires an
explicitly authorized live smoke on the exact release commit. Unsupported
runtime evidence fails as `UNSUPPORTED_CAPABILITY` before queue side effects.

## 6. Recovery and explicit closure

- Generic recovery never promotes a queue operation.
- A correlated continuation may recover only its exact turn.
- `abandon` is a human-selected local closure, never automatic retry or proof
  of remote cancellation.
- Any open queue operation may be abandoned because generic queue recovery is
  deliberately disabled.
- A continuation may be abandoned only before authoritative correlation;
  a correlated timeout must be recovered.
- Ordinary exact-ID ambiguity keeps the RFC-0001 recovery rule.

Repeated or restarted `abandon` returns the same terminal receipt without
creating another receipt or side effect.

## 7. Evidence boundary

Queue workspace evidence spans the active owner plus the queued turn. It proves
final scope and checks, not per-turn filesystem causality. Use idle `continue`
when isolated attribution is required. Raw prompt and result content remain out
of the journal and default receipt.

Desktop project creation, direct writes to Codex private state, automatic
daemon startup, Telegram delivery, and general scheduling remain out of scope.
